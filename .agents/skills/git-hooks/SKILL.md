# Git Hooks

Enforce the suite's rules at the git level so they apply to every commit — typed
by a human, this agent, or any other tool — not just when a skill is active.

## What it enforces
**`commit-msg` hook:**
1. Blocks AI attribution: `Co-authored-by:` for AI tools, `🤖 Generated …`,
   `Generated with Claude/Copilot/Cursor/Codex`, `noreply@anthropic.com`.
2. Requires a Conventional Commit subject: `type(scope)?!: subject`, subject ≤ 72 chars.
   Allowed types: feat, fix, perf, refactor, docs, style, test, build, ci, chore, revert.
   Merge/revert/fixup commits are allowed through.

**`pre-commit` hook:** refuses commits made directly on `main`/`master`
(override once with `ALLOW_MAIN=1 git commit …`).

## Workflow
1. From the target repository root, install the hooks:
   ```sh
   scripts/install-hooks.sh
   ```
   This copies `hooks/commit-msg` into the repo's hooks path and makes it
   executable. It respects a configured `core.hooksPath` if one is set.
2. Verify:
   ```sh
   git commit --allow-empty -m "chore: verify hook"      # should pass
   git commit --allow-empty -m "bad message"             # should be rejected
   ```
3. To share across the team, commit the `hooks/` dir into the repo and point git
   at it once per clone:
   ```sh
   git config core.hooksPath .githooks && cp hooks/commit-msg .githooks/
   ```

## Troubleshooting
- Hook not firing: check `git config core.hooksPath` and that the file is executable.
- Bypass for one commit (discouraged): `git commit --no-verify`.
- See `references/hooks-guide.md`.

## Files
- `hooks/commit-msg` — message enforcement hook (POSIX sh).
- `hooks/pre-commit` — refuses commits on main/master (POSIX sh).
- `scripts/install-hooks.sh` — install both hooks into the current repo.
- `references/hooks-guide.md` — how hooks are resolved, sharing, bypassing.
