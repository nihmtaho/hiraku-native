# Git Release

Produce a clean, consistent release from the commits since the last release.

## Hard rules
- NEVER add AI co-author or "generated by AI" lines to tags, notes, or commits.
- Propose the version bump and show the drafted notes BEFORE tagging or pushing.
- Only tag from a clean working tree on the release branch (usually `main`).

## Workflow
1. Collect the changes since the last release:
   ```sh
   scripts/changes-since-last-tag.sh            # or: scripts/changes-since-last-tag.sh <base-ref>
   ```
2. Decide the next version with SemVer (see `references/release-template.md`):
   breaking → major, `feat` → minor, `fix`/others → patch.
3. Draft the notes into a file (the script groups commits into the standard
   sections and writes the compare link):
   ```sh
   scripts/draft-release-notes.sh "" vX.Y.Z > .git/RELEASE_NOTES.md
   ```
   Edit `.git/RELEASE_NOTES.md` for clarity, then verify no AI trailers:
   ```sh
   ../git-commit/scripts/guard-no-ai-trailer.sh .git/RELEASE_NOTES.md
   ```
   (Each skill also ships its own copy of the guard under `scripts/`.)
4. Show the user the version + notes and get approval.
5. Tag and push:
   ```sh
   git tag -a vX.Y.Z -F .git/RELEASE_NOTES.md
   git push origin vX.Y.Z
   ```
6. If using GitHub, publish with the same notes:
   ```sh
   gh release create vX.Y.Z --title "vX.Y.Z" --notes-file .git/RELEASE_NOTES.md
   ```

## Files
- `references/release-template.md` — section order, SemVer rules, worked example.
- `scripts/changes-since-last-tag.sh` — commits since the latest tag (or a given ref).
- `scripts/draft-release-notes.sh` — group commits into the templated changelog.
- `scripts/guard-no-ai-trailer.sh` — reusable trailer check (`--strip` to clean).
