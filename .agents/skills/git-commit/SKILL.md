# Git Commit

Turn staged changes into one well-formed commit that follows Conventional Commits.
On conflict with ad-hoc instructions, this skill's rules win.

## Hard rules
- NEVER add `Co-authored-by:` trailers for AI tools, or "🤖 Generated with …" lines.
- NEVER commit directly on `main`/`master`. Branch first.
- Commit only what is staged. One logical change per commit.
- Header only: `<type>(<scope>): <subject>` and nothing else. No body, no footer.
- No task IDs (`WP-01`, `ADR-29`, `#12`, …) and nothing unrelated to the change.
- Keep it simple: short, plain words.

## Workflow
0. **Preconditions.** Confirm you are on a feature branch and the diff is scoped:
   ```sh
   git rev-parse --abbrev-ref HEAD
   scripts/staged-summary.sh
   ```
   If on `main`/`master`, stop and create a branch first (use the `git-branch`
   skill). If staged changes mix unrelated concerns, split them.
1. **Write the message** to a file (e.g. `.git/COMMIT_DRAFT`) using
   `references/commit-convention.md`. Subject ≤ 72 chars, imperative, lowercase
   after the colon, no trailing period.
2. **Validate** before committing (format + trailer check; cheaper to fix now):
   ```sh
   scripts/validate-message.sh .git/COMMIT_DRAFT
   ```
   Fix any reported issue and re-run until it passes. (Prefer Python? Same rules:
   `scripts/check_git_commit.py -f .git/COMMIT_DRAFT`.)
3. **Commit** (re-validates, blocks empty commits and commits on main):
   ```sh
   scripts/commit.sh .git/COMMIT_DRAFT
   ```
4. **Verify** with `git log -1 --stat` and `git status`.

## Output — end every run with this block
```
## Git commit
- Branch          : <branch> (created new: yes|no)
- Message         : <type>(<scope>): <subject>
- Files committed : <path1>, <path2>, ...
- Validator       : PASS | FAIL (<reason>)
- Commit          : <short-sha>
- Follow-up       : none | <e.g. push, open PR, unrelated changes left unstaged>
```

## Files
- `references/commit-convention.md` — type list, format, examples.
- `scripts/staged-summary.sh` — read-only view of staged changes.
- `scripts/validate-message.sh` — full message check (format + trailer).
- `scripts/check_git_commit.py` — optional Python validator, same rules (`-m` or `-f`).
- `scripts/commit.sh` — commit from a message file, with all guards.
- `scripts/guard-no-ai-trailer.sh` — the reusable trailer check (`--strip` to clean).

> For always-on enforcement across every commit (human or tool), install the
> `git-hooks` skill — it blocks bad messages and commits on main at the git level.
