# Git PR Creator

Turn the current branch's work into a reviewable pull request.

## Hard rules
- NEVER add AI co-author or "generated by AI" lines to the PR title or body.
- Diff against the base branch's **merge-base**, not raw `HEAD`, so the PR shows
  only this branch's work.
- Push the branch before creating the PR. Confirm the base branch with the user
  if detection is uncertain.

## Workflow
1. Summarize what this branch changes relative to its base:
   ```sh
   scripts/changes-vs-base.sh            # or: scripts/changes-vs-base.sh <base-branch>
   ```
2. Draft the PR into a file using `references/pr-template.md`. First line of the
   body is NOT the title — pass the title separately. Title follows Conventional
   Commits (e.g. `feat(ui): add dark mode`).
   ```sh
   # write .git/PR_BODY.md from the template, then:
   scripts/guard-no-ai-trailer.sh .git/PR_BODY.md
   ```
3. Show the user the title + body and get approval.
4. Push and open the PR (the script pushes the branch, guards the body, and
   fails clearly if `gh` is missing):
   ```sh
   scripts/create-pr.sh "feat(ui): add dark mode" .git/PR_BODY.md main
   ```
   Add `--draft` or any other `gh pr create` flags at the end.

## Files
- `references/pr-template.md` — title rules + body sections (Summary, Changes,
  Testing, Risk, Linked issues).
- `scripts/changes-vs-base.sh` — commits + diffstat vs the base merge-base.
- `scripts/create-pr.sh` — push + `gh pr create`, with the trailer guard.
- `scripts/guard-no-ai-trailer.sh` — reusable trailer check (`--strip` to clean).
