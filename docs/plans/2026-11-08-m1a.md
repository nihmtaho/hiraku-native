# M1a Implementation Plan — iPhone vertical slice

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the P0 iPhone vertical slice (WP-01…WP-10): workspace and contract, SQLite store, FFI bridge, FSRS grading, kana typing, design system, folder/deck/word CRUD, study and flashcard flows.

**Architecture:** Go core (`core/`) owns contract, storage, scheduling and normalization; Swift packages own UI and bridge. Contract lives in `core/proto/hiraku/v1`, generated code is never edited. Every multi-table write runs in one core transaction; Swift never opens SQLite.

**Tech Stack:** Go 1.27, `mattn/go-sqlite3`, `google.golang.org/protobuf`, buf; Swift 6, SwiftUI, `swift-protobuf`, XCFramework.

**Spec:** `docs/architecture/ARCHITECTURE.md` v2.2, `docs/product/spec.md`, `docs/product/use-cases.md`, `docs/product/DESIGN.md`, `COPY.md`.

## Global Constraints

- Contract: `core/proto/hiraku/v1` is the only source; never edit `gen/`; never reuse field numbers.
- Only `core/ffi` imports `"C"`; only `HirakuBridge` calls `hk_*`.
- Go: no `time.Now()` in `domain`/`service` (time arrives as `now_ms`), no `net`, no globals outside `ffi`, no `unsafe` outside `ffi`.
- Swift: features import only `HirakuModels` and `DesignSystem` (plus `StudyKit` for study); no `HirakuBridge` in features; no feature-to-feature imports.
- Swift 6 strict; no `try!`, no force unwrap in business logic; UI uses `HK*` tokens, `AppIcon`, String Catalog.
- Every PR updates `CHANGELOG.md` `[Unreleased]`, `ROADMAP.md` §11 and the Kanban row.
- Decisions applied: Q-19 soft delete 30 days, Q-20 `sub_code` enum, Q-21 option B, Q-22 Review = known, Q-24 app-level AppStorage settings, Q-27 backup after M1a, Q-28 "bộ thẻ"/"hồ sơ".
- Device: simulator on macOS is the standard verification target (Q-11); real-device results are recorded as unverified debt.

## Review Focus

- Empty and one-item data: empty folder list, last deck deleted, last card graded, zero due cards must render a defined empty state, not a crash.
- Interrupted writes: app killed mid-grade or mid-delete leaves SQLite consistent (WAL + transaction) and the next open succeeds.
- Time boundaries: grading at the day boundary and across DST-free UTC day rolls must use `now_ms` from Swift, not the clock inside core.
- IME edge: marked text, composition, and full-width vs half-width input in the typing screen must not double-insert or drop kana.
- Large data: 50,000 notes and 200,000 review logs must page lists and build the queue without loading everything into memory.
